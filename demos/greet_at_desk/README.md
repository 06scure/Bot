# 到岗打招呼闭环 demo

复用现有 `yolo_camera` 的 Camera、RGA 和 Detector，以及 `rk809_tts` 的中文合成/播放模块。是独立验证程序，尚未装配 HTTP 或 systemd 服务。

```text
启动合成固定问候语 → 本次进程私有 WAV 缓存
摄像头 → YOLO26 person → ROI → 连续帧/离岗/冷却 → 入队 → 播放线程 → RK809
```

## 板端运行

```bash
cd /root/bot_demos/demos/greet_at_desk
bash build.sh                  # 同时执行纯逻辑 CTest
bash run.sh                    # 板端桌面窗口，q/Esc 或 Ctrl+C 退出
bash run.sh --headless --seconds 60
```

先关闭占用 `/dev/video0` 的其他摄像头程序。默认使用板端 cat 用户的 XFCE 桌面（DISPLAY=:0）；SSH 无桌面时用 `--headless`。`--seconds` 从 TTS 预热和摄像头初始化完成后开始计时。测试结束会停止播放线程、释放 RKNN/摄像头、删除本次进程的临时缓存。

默认配置：640×480，人体分数 ≥0.60，归一化 ROI `[0.15,0.25,0.85,0.95]`，人体框中心落入 ROI，连续 5 帧确认，持续缺席 1000 ms 复位，问候冷却 600000 ms。阈值在 `src/trigger/desk_state_machine.hpp`，相机、模型路径和问候文本在本目录 `main.cpp`，修改后重新编译。

- 一直在场只问候一次，冷却结束不会在原地补播。
- 离开会复位在场状态，不会清除冷却。冷却内再来仍报告到岗，但不播放。
- 成功入队才启动冷却；入队成功和播放成功是不同事件。
- 缓存忙时拒绝重复请求，不积压问候。请求上限为一条（包含正在播放的请求）。
- 相机/推理错误直接报错退出，不能假装“无人”继续推进离岗判断。
- 模型在启动时加载并合成，随后存活到进程结束；运行期间只播放本次合成缓存，不争抢 NPU。
- 缓存仅在本进程内生效，文本或模型变化后下一次启动必定重新合成，不读取旧 WAV 作为降级。

## 验证

```bash
./build/desk_state_test
./build/greet_replay_test
```

第一条是 32 项不依赖硬件的状态机断言。第二条**会实际播放两次中文**，检测事件使用明确标记的合成数据：3 次到岗中 1 次处于冷却，最终 2 次播放。它不等同于真人走入摄像头的验收。回放将音频保存在 `replay-test.wav`。

真人验收：

1. 先离开画面，再进入窗口蓝色 ROI，等待连续帧确认。日志应依次出现 `arrival_confirmed`、`greeting_queued`、`playback_complete`。
2. 留在画面，不应重复问候；短暂遮挡不应重播。
3. 离开超过 1 秒后再进入，10 分钟冷却内应只有到岗事件，无问候。
4. 如需缩短测试等待，在配置中临时调小冷却并重新编译，完成后恢复；重新启动会重置本 demo 的冷却。

完整实测记录和 C++ 讲解见 [验证报告](../../docs/RK809与打招呼Demo.md)。
