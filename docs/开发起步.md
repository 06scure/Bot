# 第一批 C++ 框架使用说明

本批代码用于在没有设备时准备工程边界，尚未实现机器人功能。

## 当前包含什么

- C++17 / CMake 构建入口，不联网下载依赖。
- `bot_logic`：普通检测结果、状态机配置、状态枚举和待实现接口。
- `bot`：命令行入口、默认配置、启动说明和顶层异常处理。
- JSON 配置样例与 Catch2 测试接入位置。

目前仅状态机初始化、状态名称和状态查询有实现。JSON 加载、状态更新和
问候入队确认会抛出 `not implemented` 错误，不会返回虚假的成功结果。
没有设备线程、模型推理、音频播放、HTTP 服务或已完成的测试用例。

## 无设备构建

开发主机安装支持 C++17 的编译器与 CMake 3.16 或以上后，在项目根目录执行：

```text
cmake -S . -B build
cmake --build build --config Debug
```

Linux / 单配置构建运行 `./build/bot`，Visual Studio 多配置构建通常运行
`./build/Debug/bot.exe`。程序打印默认配置来源与 `ABSENT` 状态后退出，
这只代表框架入口运行成功，不代表任何端侧功能已验证。

`bot --help` 显示帮助。`bot --config config/bot.json` 目前会明确失败，
需先实现 `load_config`。后续相对模型路径统一以进程工作目录为基准。

## 推荐实现顺序

1. 阅读 `src/vision/detection.hpp`，固定人体框与 ROI 的坐标约定。
2. 补全 `src/trigger/desk_state_machine.cpp`。先区分在场事实与问候资格：
   连续五帧确认到岗，短暂漏检不复位，离开不清除冷却。
3. 按 `tests/desk_state_machine_test.cpp` 的清单实现逻辑测试，注入时间，
   不使用 sleep。分别断言到岗事件和 `greeting_allowed` 问候资格。
4. vendor 固定版本的 nlohmann/json，实现配置解析和严格校验；引入 spdlog。
5. 拿到设备后，分别验证摄像头、RGA/YOLO、ALSA、MeloTTS。
6. 增加 capture、vision、skill、tts、audio、http 模块及 App 装配，
   最后接通视觉循环与容量受限的 TTS 请求队列。

框架建议以“请求成功入队”为冷却起点；冷却结束但人仍在场时不补播。
队列满时记录失败，本次到岗不自动重试。以上属于待实现的行为约定，
不是当前已有能力。手动问候是否共享自动冷却，在实现 HTTP 前确定。

## 测试依赖与运行

默认 `BOT_BUILD_TESTS=OFF`，不要求本机已有 Catch2。准备执行测试时，
把固定版本 Catch2 v3 的源码及许可证放到 `third_party/Catch2/`，
在测试文件中添加真实用例，再执行：

```text
cmake -S . -B build -DBOT_BUILD_TESTS=ON
cmake --build build --config Debug
```

进入 `build` 目录运行 `ctest -C Debug --output-on-failure`。
依赖缺失时配置阶段明确报错；没有用例时也不应视为测试通过。
不要添加无断言的“成功”占位测试。

## 后续模块边界

- `main.cpp` 保持简短；线程、队列、装配和按序关闭放在 `app/`。
- 状态机仅依赖标准库，不包含设备 SDK 头文件。
- 技能产生语音请求，播放器只负责播放，两者由 App 连接。
- 视觉线程独占状态机，HTTP 读取经过同步的快照。
- 失败的采集/推理不等同于“无人”，必须单独上报健康状态。
- 普通信号处理器不调用 HTTP stop、日志或锁操作，退出动作由正常线程处理。
- 同线程取帧不保证拿到最新图像；板端接入时需要验证驱动缓冲与帧时间戳。
- 工程、模型、驱动和实板性能分别验证，不把框架构建成功当成功能验收。

头文件与实现文件放在同一功能目录；当前无需公共 include 目录、通用事件总线
或抽象硬件基类。新增文件前优先查看现有文件中的 TODO。
